# Requirements — URL Shortener (v1)

This document defines *what* the system must do. Design and implementation belong
to later phases.

## 1. Users

| Actor | Description |
|-------|-------------|
| **Creator** | Authenticated via API key. Creates and manages short links; views stats and edit history. |
| **Visitor** | Unauthenticated. Follows a short URL and is redirected. |

API keys for v1 are issued manually (no self-service registration).

## 2. Functional requirements

### FR-1 — Shorten a URL

Given a valid long URL, the system returns a unique short code and the full short URL.
Malformed or invalid URLs are rejected with a clear error.

### FR-2 — Custom aliases

A creator may supply their own alias. Accepted when available and well-formed:

- Length: 3–64 characters
- Alphabet: alphanumeric and hyphens
- Matching: case-insensitive

Rejected when taken, malformed, or on the reserved-word list (`api`, `stats`, `health`,
and all other app routes).

### FR-3 — Redirect

Given a short code, redirect the visitor to the current destination URL.
Unknown codes return "not found."

### FR-4 — Distinct dead-link handling

Expired or deleted links are handled differently from never-existed ones:

- Removed / expired → "this link was removed"
- Never existed → "this link doesn't exist"

### FR-5 — Click capture

Every successful redirect records a click event: timestamp, referrer, user agent.

#### FR-5a — Visitor fingerprinting

Derive a visitor fingerprint from IP + user agent; store only the hash, never the raw IP.

#### FR-5b — Approximate unique visitors

Count unique visitors per link using the fingerprint within a 24-hour window.
Uniqueness is **approximate by design**; the product/API must state this.

### FR-6 — Stats retrieval

A creator can fetch, for their own link:

- Total clicks
- Unique visitor count (per FR-5b)
- Paginated list of click events (with referrer / UA breakdown)

### FR-7 — Link lifecycle

A creator can:

- List their links
- Edit a link's destination
- Soft-delete a link
- Optionally set an expiration time at creation

#### FR-7a — Edit audit trail

Every destination change is recorded with old URL, new URL, and timestamp.
History is retrievable by the owner.

### FR-8 — Creator identity

Creation and all management operations require an API key.
Redirects are public and require no identity.

## 3. Out of scope (v1)

- User registration / UI (API keys issued manually)
- QR codes
- Custom domains
- Link preview / malware scanning

## 4. Assumptions & open questions

| # | Assumption / question | Status |
|---|----------------------|--------|
| A1 | Short codes are generated by the system when no custom alias is supplied | Assumed |
| A2 | Soft-deleted and expired links both surface as "removed" (FR-4) | Assumed |
| A3 | Stats and audit trail are API-only for the owning creator | Assumed |
| Q1 | Exact short-code generation rules (length, alphabet) when no alias | Open — Phase 3 |
| Q2 | Pagination defaults/limits for click lists | Open — Phase 3 |
| Q3 | Error representation (shape, codes) | Open — Phase 3 |

## 5. Deferred to later phases

Not part of Phase 0; revisit when that phase starts:

- Express + TypeScript, PostgreSQL (Prisma), Redis, Zod, pino
- N stateless application instances behind a load balancer
